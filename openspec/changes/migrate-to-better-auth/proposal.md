# Proposal

## Why

The current OIDC server has a partial OAuth 2.0 implementation with custom authentication code that lacks critical security features and OAuth flows. Only basic email/password authentication and a static OIDC configuration document are implemented, while the declared authorization code flow, token endpoint, JWKS, refresh tokens, and device authorization are not functional. Migrating to betterAuth provides a production-grade OAuth 2.1 compliant implementation with built-in security practices, full OIDC support, and a maintainable codebase.

## What Changes

- **BREAKING**: Replace Express framework with Hono for lighter weight and native Web Standard support
- **BREAKING**: Replace custom authentication implementation with betterAuth framework
- **BREAKING**: Replace custom user table schema with betterAuth's schema (user, session, account, verification tables)
- **BREAKING**: Replace custom password hashing (HMAC-SHA256) with betterAuth's secure password hashing
- **BREAKING**: Remove all custom auth controllers, routes, and middleware (auth controller, token utils, auth middleware)
- Add @better-auth/oauth-provider plugin for OAuth 2.1 and OIDC functionality
- Add @better-auth/drizzle-adapter for PostgreSQL integration
- Add JWT plugin for JWKS endpoint and token signing
- Generate and migrate to new database schema (oauthClient, oauthRefreshToken, oauthAccessToken, oauthConsent, oauthClientAssertion tables)
- Auto-generate OAuth 2.1 endpoints (authorize, token, userinfo, introspect, revoke, device code, client registration)
- Auto-generate OIDC discovery endpoints (/.well-known/openid-configuration, /.well-known/oauth-authorization-server)
- Configure OAuth provider with both admin-managed and dynamic client registration
- Implement login and consent pages for OAuth authorization flow

## Capabilities

### New Capabilities

- `oauth-provider`: OAuth 2.1 authorization server with OpenID Connect support, including authorization code flow, refresh tokens, client credentials, device authorization, JWKS endpoint, token introspection/revocation, and client management
- `user-authentication`: User authentication with email/password, secure session management, and password reset

### Modified Capabilities

None (no existing specs)

## Impact

- **Code**: Complete rewrite of authentication layer, removal of src/app/auth/ and src/app/oidc/ directories, replacement of src/server.ts and src/app/index.ts with Hono-based implementation
- **Database**: Full schema migration - users table replaced with betterAuth schema, addition of 8 new OAuth-related tables
- **Dependencies**: Add better-auth, @better-auth/oauth-provider, @better-auth/drizzle-adapter, hono; remove express, jsonwebtoken, custom auth utilities
- **APIs**: All OAuth 2.1 endpoints auto-generated by betterAuth at /api/auth/*, removal of custom /v1/auth/* endpoints
- **Issuer**: Issuer URL remains https://accounts.debeshghorui.com
